# ADR-0053: Kotlin Noise port, phone enrollment over the link, JVM checks without a test framework

- Status: Accepted
- Date: 2026-10-29

## Context
The Android Noise channel was a stub (noise-java is not on Maven Central). The M-16 spec says the phone app guides enrollment through the EnrollmentPort, while biometrics stay local to the owner's devices. Android unit tests normally use JUnit, whose EPL licence is outside the R-05 allow-list.

## Decision
- Port Noise_XX_25519_ChaChaPoly_BLAKE2s to Kotlin in a pure-JVM module `android/core`, using Bouncy Castle (MIT-style) primitives. Interop is proven by byte-identical vectors generated by the Python side (`scripts/make_noise_vectors.py` → `tests/vectors/noise_xx.json`), checked by pytest and by the Kotlin checks.
- Messages larger than a Noise frame are fragmented (1 flag byte + ≤60 kB chunk per frame), same on both sides.
- The phone only captures and guides; the pod's `face_match/remote.py` EnrollmentServer runs the opt-in, consent, quality and template steps. Frames cross only the encrypted link and are zeroed after sending.
- JVM checks are a self-contained harness (`jvmChecks`, part of `:core:check`), so no test-framework licence enters the project.

## Consequences
The BLE GATT transport is not built (needs pod hardware); `PodLink` takes any frame transport. Nothing has run on a phone.
